## 5. Подготовка данных

### 5.1. Загрузка данных

На первом этапе датасет загружается с помощью Pandas.

После загрузки проверяются:
- количество строк и столбцов;
- названия признаков;
- типы данных;
- пропущенные значения;
- наличие дублирующихся записей;
- основные статистические характеристики.

Первичный анализ помогает определить структуру данных и выявить проблемы, которые могут повлиять на качество обучения.

### 5.2. Определение признаков и целевой переменной

Для обучения модели необходимо разделить данные на две части:

- **Признаки `X`** — переменные, используемые моделью для построения предсказаний.
- **Целевая переменная `y`** — числовой показатель, который модель должна предсказать.

Выбор целевой переменной зависит от структуры датасета и постановки задачи.

Поскольку используется датасет Dota 2, перед обучением необходимо убедиться, что выбранная целевая переменная действительно подходит для регрессии.

Если требуется предсказать категорию или класс, а не числовую величину, задача может относиться к классификации, а не к регрессии.

### 5.3. Разделение на обучающую и тестовую выборки

Данные разделяются на две части с помощью `train_test_split`.

Используется следующее соотношение:

- 80% данных — обучающая выборка.
- 20% данных — тестовая выборка.
- `random_state=42` — для воспроизводимости результатов.

Обучающая выборка используется для обучения модели и настройки параметров предобработки.

Тестовая выборка используется для оценки качества предсказаний на ранее не использованных наблюдениях.

## 6. Предобработка данных

### 6.1. Обработка пропущенных значений

Пропущенные значения могут препятствовать обучению модели или приводить к ошибкам при обработке данных.

В зависимости от типа признака и характера пропусков могут применяться следующие стратегии:

- заполнение числовых признаков медианой;
- заполнение числовых признаков средним значением;
- заполнение категориальных признаков наиболее частой категорией;
- удаление записей или признаков, если это обосновано анализом данных.

Выбор стратегии должен учитывать свойства конкретного датасета.

### 6.2. Масштабирование признаков

Для стандартизации числовых признаков может использоваться `StandardScaler`.

Стандартизация преобразует признаки с учётом среднего значения и стандартного отклонения, вычисленных на обучающих данных.

Это помогает привести признаки к сопоставимому масштабу и облегчает сравнение коэффициентов модели при соответствующих условиях.

### 6.3. Использование Pipeline

`Pipeline` позволяет объединить несколько этапов обработки и обучения в единую последовательность.

Например, пайплайн может включать:

1. Заполнение пропущенных значений.
2. Масштабирование числовых признаков.
3. Кодирование категориальных признаков, если они присутствуют.
4. Обучение модели линейной регрессии.

Такой подход упрощает поддержку кода и обеспечивает одинаковую последовательность преобразований при обучении и предсказании.

### 6.4. Предотвращение утечки данных

Утечка данных возникает, когда при подготовке модели используется информация, которая должна оставаться недоступной на этапе обучения.

Чтобы избежать этой проблемы:

1. Сначала данные разделяются на обучающую и тестовую выборки.
2. Параметры предобработки вычисляются только по обучающей выборке.
3. Модель обучается на обучающих данных.
4. К тестовым данным применяются уже настроенные преобразования.
5. Качество оценивается на тестовой выборке.

Если используется `Pipeline`, его можно обучить на `X_train` и `y_train`, а затем применить к `X_test` для получения предсказаний.

## 7. Обучение модели линейной регрессии

Для решения задачи используется алгоритм `LinearRegression` из Scikit-learn.

Линейная регрессия строит зависимость между входными признаками и числовой целевой переменной.

В общем виде модель можно представить формулой:

\[
\hat{y} = b + w_1x_1 + w_2x_2 + \cdots + w_nx_n
\]

где:

- \(\hat{y}\) — предсказанное значение;
- \(b\) — свободный коэффициент;
- \(w_i\) — коэффициент соответствующего признака;
- \(x_i\) — значение признака;
- \(n\) — количество признаков.

Модель подбирает коэффициенты так, чтобы минимизировать сумму квадратов ошибок на обучающих данных.

После обучения модель используется для получения предсказаний на тестовой выборке.

## 8. Оценка качества модели

Для оценки регрессионной модели используются метрики MAE, MSE, RMSE и \(R^2\).

### 8.1. MAE — Mean Absolute Error

MAE показывает среднюю абсолютную разницу между фактическими и предсказанными значениями.

\[
MAE = \frac{1}{n}\sum_{i=1}^{n}|y_i-\hat{y}_i|
\]

Чем меньше значение MAE, тем меньше средняя абсолютная ошибка модели.

Метрика выражается в тех же единицах, что и целевая переменная.

### 8.2. MSE — Mean Squared Error

MSE представляет собой среднее значение квадратов ошибок.

\[
MSE = \frac{1}{n}\sum_{i=1}^{n}(y_i-\hat{y}_i)^2
\]

Большие ошибки оказывают на MSE более сильное влияние, чем небольшие.

Значение метрики выражается в квадрате единиц целевой переменной.

### 8.3. RMSE — Root Mean Squared Error

RMSE является квадратным корнем из MSE.

\[
RMSE = \sqrt{MSE}
\]

Эта метрика позволяет оценить величину ошибки в тех же единицах, что и целевая переменная.

Чем меньше RMSE, тем ближе предсказания модели к фактическим значениям с точки зрения квадратичной ошибки.

### 8.4. Коэффициент детерминации \(R^2\)

\(R^2\) показывает, насколько хорошо модель объясняет изменчивость целевой переменной относительно базового прогноза средним значением на оцениваемой выборке.

Интерпретация:

- \(R^2 = 1\) — идеальные предсказания.
- \(R^2\), близкий к 1, — модель объясняет значительную часть вариации целевой переменной.
- \(R^2 = 0\) — качество относительно базового прогноза средним значением не улучшено.
- \(R^2 < 0\) — модель на этой выборке работает хуже такого базового прогноза.

Значение \(R^2\) необходимо интерпретировать вместе с другими метриками и с учётом особенностей задачи.

### 8.5. Сравнение метрик

| Метрика | Что измеряет | Желаемое направление |
|---|---|---|
| MAE | Среднюю абсолютную ошибку | Чем меньше, тем лучше |
| MSE | Средний квадрат ошибки | Чем меньше, тем лучше |
| RMSE | Корень из среднего квадрата ошибки | Чем меньше, тем лучше |
| \(R^2\) | Качество объяснения вариации целевой переменной | Чем ближе к 1, тем лучше |

Фактические значения метрик необходимо получить после запуска программы и внести в итоговый анализ.

## 9. Анализ коэффициентов модели

После обучения исследуются коэффициенты модели, доступные через `model.coef_`, и свободный коэффициент `model.intercept_`.

Коэффициенты позволяют изучить направление связи между признаками и предсказанием при условии, что остальные признаки остаются неизменными.

- Положительный коэффициент означает, что увеличение признака связано с увеличением предсказанного значения.
- Отрицательный коэффициент означает, что увеличение признака связано с уменьшением предсказанного значения.
- Коэффициент, близкий к нулю, указывает на небольшой линейный вклад признака в рамках обученной модели.

При сравнении коэффициентов важно учитывать масштабирование, кодирование категорий и возможную корреляцию между признаками.

Даже после стандартизации коэффициенты не всегда позволяют однозначно определить важность признаков, особенно при наличии мультиколлинеарности.

## 10. Анализ остатков

Остаток — это разница между фактическим и предсказанным значением.

\[
e_i = y_i-\hat{y}_i
\]

Анализ остатков помогает определить, насколько хорошо линейная модель описывает данные.

Для исследования строится график остатков в зависимости от предсказанных значений.

### Что необходимо проверить

**1. Случайное распределение остатков**

Если остатки хаотично располагаются вокруг нулевой линии, это может свидетельствовать об отсутствии выраженного систематического паттерна.

**2. Неодинаковый разброс ошибок**

Если разброс остатков заметно увеличивается или уменьшается при изменении предсказанных значений, это может указывать на гетероскедастичность.

**3. Систематические закономерности**

Изогнутые структуры или другие устойчивые паттерны могут указывать на то, что линейная модель не полностью описывает зависимость.

**4. Необычно большие остатки**

Большие по модулю остатки могут указывать на наблюдения, для которых модель делает неточные предсказания. Такие наблюдения необходимо исследовать отдельно.

График остатков позволяет выявить возможные проблемы модели, но сам по себе не доказывает выполнение всех статистических допущений линейной регрессии.
